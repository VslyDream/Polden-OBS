# Контракт Polden OBS ↔ отдельный плагин Premiere Pro

> Архив прототипа версии 0.0.1. Начиная с Polden OBS 0.1.0 интеграция удалена; описанные ниже сервер, ресурсы и расширение больше не входят в приложение.

Статус на 01.10.2026: ниже разделены **работающий в коде OBS прототип v0** и **предлагаемый контракт v1**. v1 ещё не реализован; разработчику отдельного плагина нельзя считать его доступным без обновления OBS. Целевая версия Premiere — 25.6.2.

## Граница ответственности

- Polden OBS выбирает игру при старте записи, конвертирует файл, проверяет копию в конечной папке, хранит очередь и показывает пользователю статусы. В сеть не передаются байты видео: передаётся абсолютный путь к уже готовому MP4.
- Плагин внутри Premiere обращается к OBS по `http://127.0.0.1:37941`, проверяет открытую Production, создаёт bin, импортирует медиа в указанный `Footage.prproj`, сохраняет проект и по **отдельной кнопке** добавляет запись в конец активной секвенции.
- Плагин выступает **HTTP-клиентом**. Ему не требуется свой сервер, открытый порт или панель, которую пользователь держит открытой. Adobe документирует `fetch`, `plugin.create()` и `hostUIContext.hideFromMenu` для UXP 25.6; фактический скрытый автозапуск и установка на этой машине пока не подтверждены.
- Исходники плагина могут жить в другом репозитории. В этом репозитории пока есть прототип `premiere/polden-bridge`, встроенный в OBS; при разделении проектов его нужно заменить версионированным артефактом плагина. Секрет связи создаёт OBS при установке, в репозиторий и готовый артефакт его не включать.

## v0: что доступно сейчас

Адрес: `http://127.0.0.1:37941`. Все запросы содержат `X-Polden-Key: <секрет из bridge-config.json>`; OBS сейчас записывает этот файл рядом с устанавливаемыми файлами расширения. Ответы — JSON в UTF-8. Расширение опрашивает сервер примерно раз в 2,5 секунды.

| Запрос | Ответ / смысл |
| --- | --- |
| `GET /next` | `{}` либо `{ "id", "action", "filePath", "projectPath", "binPath" }`. `action` равен `import` или `timeline`. |
| `POST /result` | Тело `{ "id", "action", "ok", "error"? }`; успешный ответ `{ "accepted": true }`. При несовпадении ожидаемой команды — HTTP 409. |

`filePath` — абсолютный путь к полностью скопированному MP4; `projectPath` — абсолютный путь к `Footage.prproj`; `binPath` — путь bin внутри Premiere, например `1_VIDEO/2026-10-01`. Команда `timeline` должна при необходимости сначала импортировать файл. Плагин обязан проверить, что активный проект находится в нужной Production, а для `timeline` — что активна секвенция. Не редактировать `.prproj` на диске напрямую.

Пример ответа `GET /next` (синтетические локальные пути):

```json
{
  "id": "84ea9b5e-24b0-4d4c-a05d-b6625bce0c5d",
  "action": "import",
  "filePath": "D:\\Polden-test\\02_Assets\\01_VIDEO\\2026-10-01\\Vasiliy_2026-10-01-16-03-12.mp4",
  "projectPath": "D:\\Polden-test\\01_Test_Production\\00_Footage\\01_Test_Footage.prproj",
  "binPath": "1_VIDEO/2026-10-01"
}
```

Текущий v0 достаточен для первого прототипа отдельного плагина, но у него нет согласования версии, явного контекста Premiere и срока действия команды. Если подтверждение потеряно после вставки на таймлайн, повтор может создать дубликат; автоматический повтор такой операции небезопасен.

## Предлагаемый v1: что согласовать перед стабильным релизом

Формат: **HTTP на `127.0.0.1` + JSON UTF-8**, версия в пути `/v1`, секрет в заголовке `X-Polden-Key`. В манифесте UXP разрешить только `http://127.0.0.1:37941`, без доступа ко всей сети. Тело видео и содержимое Premiere-проекта через API не передавать.

| Запрос | Назначение |
| --- | --- |
| `GET /v1/hello` | Согласовать `protocolVersion`, `obsVersion`, `instanceId` и поддерживаемые действия; при несовместимости показать ошибку в обеих программах. |
| `POST /v1/poll` | Плагин передаёт `pluginVersion`, `premiereVersion`, свой `instanceId`, путь активного `.prproj`, GUID активной секвенции и состояние занятости. OBS возвращает одну команду либо `null`. Этот запрос также служит heartbeat. |
| `POST /v1/result` | Плагин подтверждает команду по `commandId` и сообщает `done`, `retryable_error`, `needs_user_action`, `failed` или `uncertain`; ответ OBS подтверждает приём результата. |

Команда несёт `commandId` (стабильный для повторов), `recordingId`, `projectId`, `action`, `filePath`, `productionRoot`, `footageProjectPath`, `binPath`, `createdAt`. Для `append_active_sequence` дополнительно передаётся `expectedSequenceGuid` и срок действия. Пути — строки Windows в JSON с обычным экранированием обратной косой черты; времена — ISO 8601 с часовым поясом. `action` ограничен значениями `import_footage` и `append_active_sequence`; конвертация и копирование выполняются OBS до выдачи команды.

```json
{
  "commandId": "bea44632-d291-4ac4-bbe9-80fa61726f4c",
  "recordingId": "84ea9b5e-24b0-4d4c-a05d-b6625bce0c5d",
  "projectId": "game-uuid",
  "action": "import_footage",
  "filePath": "D:\\Polden-test\\02_Assets\\01_VIDEO\\2026-10-01\\Vasiliy_2026-10-01-16-03-12.mp4",
  "productionRoot": "D:\\Polden-test\\01_Test_Production",
  "footageProjectPath": "D:\\Polden-test\\01_Test_Production\\00_Footage\\01_Test_Footage.prproj",
  "binPath": "1_VIDEO/2026-10-01",
  "createdAt": "2026-10-01T16:03:12+03:00"
}
```

### Правила выполнения

1. Импортировать лишь готовый файл по полученному пути. Проверить существование файла и соответствие открытой Production, затем найти медиа по полному пути в целевом bin; существующий элемент повторно не импортировать. После изменения сохранить `Footage.prproj` и только потом отправить `done`.
2. `append_active_sequence` выдаётся только после нажатия кнопки в OBS. На момент выполнения снова проверить Production и GUID активной секвенции; при смене контекста вернуть `needs_user_action`, **не вставлять** клип в другую секвенцию. Если Premiere не подключён, показать предупреждение; автоматическую очередь применять к импорту, а не к контекстной вставке без закреплённой секвенции.
3. Команды импорта можно безопасно переотправлять при сбое связи после проверки существующего элемента. Для таймлайна нельзя обещать строго однократное выполнение при потере подтверждения: сохранять локальный журнал `commandId`, а неоднозначный исход возвращать как `uncertain` и требовать проверки пользователем перед повтором.
4. Ошибки возвращать структурированно: код (`WRONG_PRODUCTION`, `NO_ACTIVE_SEQUENCE`, `PROJECT_LOCKED`, `MEDIA_MISSING`, `IMPORT_FAILED`, `SAVE_FAILED`, `TIMELINE_UNCERTAIN`), короткое сообщение для OBS и признак возможности повтора. Секрет не писать в логи.
5. Фоновый плагин не меняет текущую Production без явного выбора пользователя. При несовпадении проекта сообщает проблему в OBS. Плагин не должен закрывать Premiere и не должен импортировать файл, который ещё копируется.

## Сборка отдельного проекта

Плагин выпускает самостоятельный версионированный артефакт с `manifest.json` и JavaScript для Premiere 25.6.2. OBS может включать артефакт в свою сборку и при установке дописывать `bridge-config.json` с локальным адресом, версией протокола и случайным ключом. Это разделяет исходники и сохраняет бесшовное подключение без ручного ввода ключа. Поддерживаемый Adobe способ установки такого артефакта и автоматический запуск на целевой машине нужно проверить отдельно от сетевого API; текущая копия в `External` — прототип, а не подтверждённый способ доставки.

Основание API Premiere 25.6: [Project](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/project), [FolderItem](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/folderitem), [Sequence](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/sequence), [SequenceEditor](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/sequenceeditor), [UXP fetch](https://developer.adobe.com/premiere-pro/uxp/uxp-api/reference-js/global-members/data-transfers/fetch), [скрытый запуск](https://developer.adobe.com/premiere-pro/uxp/plugins/), [установка UXP](https://developer.adobe.com/premiere-pro/uxp/plugins/distribution/install/).
