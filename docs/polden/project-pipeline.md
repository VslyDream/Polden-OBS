# Проекты и пайплайн Polden

Статус: спецификация первой версии обсуждается (24.09.2026). Текущая док-панель содержит только заглушки; описанное ниже ещё не реализовано.

## Основная сущность

**Проект = игра.** Для проекта нужны устойчивый ID, название, корневая папка на LucidLink, путь к Premiere Production и проекту `Footage`, выбранный источник OBS `Захват игры` и сохранённый идентификатор его окна. Выбранный проект определяет назначение записей. Имя записывающего и шаблоны путей/имён задаются в настройках Polden; проектные значения могут их переопределять. Личные пути, список проектов и задания пайплайна хранятся локально в конфигурации Polden OBS, вне Git.

## Панель

1. Выпадающий список проектов, добавление и редактирование проекта. В форме: название игры, корень на LucidLink, папка назначения, Production/Footage и текущее окно источника `Захват игры`.
2. Шкала автоматизации с четырьмя накопительными уровнями:

   | Уровень | Действие после записи |
   | --- | --- |
   | 0 | Обычная работа OBS без действий Polden |
   | 1 | Конвертация в обычный MP4 без перекодирования |
   | 2 | Уровень 1 и доставка в папку игры на LucidLink |
   | 3 | Уровень 2 и импорт в Premiere |

3. Отдельные действия Premiere: импортировать последнюю запись в `Footage`; добавить последнюю запись в конец текущей секвенции. Рядом — состояние текущего/последнего задания и ошибки.
4. Кнопка настроек Polden: имя записывающего, шаблоны имени и путей, правила поиска проекта Premiere и параметры импорта. Перед сохранением шаблона показывать пример итогового пути.

## Предложенный шаблон пути

Из примера пользователя: `L:\{игра}\02_Assets\01_VIDEO\{дата_записи:YYYY-MM-DD}\{имя}_{время_начала_записи:YYYY-MM-DD-HH-mm-ss}.mp4`.

Пример Premiere: `L:\Meowgic\01_Meowgic_Production\00_Footage\01_Meowgic_Footage.prproj`; внутри проекта bin `1_VIDEO/{дата_записи:YYYY-MM-DD}`. Проверено, что эти папки и файл проекта Meowgic существуют в текущем LucidLink. Поиск `Footage` должен выдавать ошибку при неоднозначном результате, а не выбирать произвольный `.prproj`.

Дата и время фиксируются при начале записи, чтобы медленная конвертация или смена дня не меняла путь. При сегментации записи требуется сохранять номер сегмента в имени, чтобы файлы не перезаписывали друг друга. InfoWriter сейчас синхронизирует имя/путь с видео и создаёт CSV; судьба CSV при доставке уточняется.

## Выполнение

Путь завершённой записи берётся из OBS только после закрытия файла. Задание хранит исходный путь, ID проекта и выбранный уровень автоматизации, зафиксированные при старте записи. Этапы: `recorded -> converting -> converted -> transferring -> transferred -> importing -> imported`; ошибки не удаляют исходник и доступны для повтора. FFmpeg пишет во временный файл, проверяет результат, затем завершает переименование. Копирование в LucidLink также завершается через временный файл с проверкой размера/целостности, чтобы Premiere не увидел неполный футаж. Повтор задания не должен создавать дубликаты в папке или Premiere.

Для Premiere 25 требуется отдельное расширение внутри Premiere; подробности и версии API — в [premiere.md](premiere.md). Polden не правит `.prproj` напрямую. Отдельно проверяются открытая Production, нужный проект `Footage`, доступ на запись и активная секвенция перед вставкой на таймлайн.

## Вопросы перед реализацией

- Автопоиск путей из корня игры или все пути вводятся вручную; поведение при нескольких `Footage`.
- Переключать ли окно `Захват игры` автоматически при смене проекта.
- Уровень автоматизации общий или свой для каждой игры.
- На уровне 3 импортировать только в bin или также на таймлайн; очередь при закрытом Premiere.
- Удалять ли локальные файлы после доставки; переносить ли CSV InfoWriter.
- «Последняя запись» относится к выбранному проекту или ко всему OBS; к какому проекту отнести запись при переключении во время записи.
- Уточнить точную минорную версию Premiere 25 и проект/секвенцию, которые обычно открыты при работе.
