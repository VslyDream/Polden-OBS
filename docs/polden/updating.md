# Релизы и обновление Polden OBS

Публичные сборки: https://github.com/VslyDream/Polden-OBS/releases. Версия Polden хранится в `POLDEN_VERSION`, отдельно от версии базы OBS. Стабильный тег: `polden-v0.1.0`; архив: `Polden-OBS-0.1.0-Windows-x64.zip`. Переносимый ZIP нужно распаковать в папку, доступную пользователю для записи, и запустить `Polden OBS/bin/64bit/obs64.exe`.

Через пять секунд после запуска выполняется одна тихая проверка последнего публичного стабильного релиза через GitHub API. Отсутствие сети или релиза не мешает запуску. Если версия новее текущей и есть Windows x64 ZIP с SHA-256 от GitHub, внизу панели Polden появляется зелёный значок рядом с баг-репортом. Нажатие показывает размер, изменения и предлагает скачать обновление с перезапуском. Меню «Справка → Проверить обновления» запускает ручную проверку. Параметр `--disable-updater` отключает проверку при запуске. Маркеры отключения исходного обновлятора OBS не отключают обновления Polden.

Загрузка поддерживает прогресс и отмену. После проверки SHA-256 приложение повторно проверяет, что запись, трансляция, replay buffer, виртуальная камера и обработка файлов завершены. Помощник извлекается из ресурсов EXE, запускается без консольного окна и ждёт нормального завершения OBS не больше трёх минут. Если пользователь отменит закрытие или открыт другой экземпляр этой установки, файлы приложения не заменяются.

Помощник проверяет каждую запись ZIP, версию и хеши файлов из `polden-install.json`, запрещает выход за пределы папки и запись через junction/symlink. Настройки никогда не берутся из архива обновления. Обновляются только файлы приложения, перечисленные в манифесте; ранее поставленные файлы, исключённые из нового релиза, удаляются. Сторонние файлы и плагины сохраняются. Если новый релиз пытается занять путь стороннего файла, установка отказывается его перезаписывать.

Перед заменой в `.polden-backups/<дата-время>-<id>/` внутри установки сохраняются исходные программные файлы и копия настроек. В переносимом режиме настройки расположены в `config/obs-studio`, в обычном — в `%APPDATA%/obs-studio`. Они включают профили, сцены, проекты Polden и конфигурацию плагинов. Настройки не изменяются помощником; при ошибке замены файлов восстанавливается предыдущая версия. После успеха приложение перезапускается с тем же переносимым режимом. Сторонние плагины сохраняются, но совместимость при смене базы OBS нужно проверять отдельно.

Журнал сохраняется в папке резервной копии (`update.log`), а при ранней ошибке — в `%TEMP%/Polden-update-*/update.log`. При ошибке показывается сообщение с путём журнала. Большие временные файлы после успешной установки удаляются; резервные копии остаются для ручного восстановления. Автоматическое обновление предназначено для ZIP-установок с `polden-install.json`; рабочая сборка из репозитория обновляется сборочным скриптом.

## Подготовка и публикация

Если рабочее приложение открыто, собирайте релиз в отдельной папке:

```powershell
python scripts/build-windows.py --config Release --jobs 1 --build-dir build_polden_release --configure --no-publish
python scripts/test-windows-updater.py
python scripts/package-windows.py --build-dir build_polden_release
```

Упаковщик исключает локальную конфигурацию, персональный InfoWriter и PDB, добавляет `COPYING`, `portable_mode.txt`, `polden-install.json` и отдельный `.zip.sha256`. Персональные архивы не публикуются.

После коммита исходников и отправки ветки в GitHub:

```powershell
python scripts/release-windows.py --check
python scripts/release-windows.py --publish
```

Публикация использует существующие учётные данные Git Credential Manager, проверяет содержимое ZIP и контрольную сумму, создаёт черновик, загружает архив и SHA-256, сверяет хеши загрузки с GitHub и только затем публикует релиз. Уже опубликованный релиз скрипт не перезаписывает. Исходники доступны по тегу релиза.
